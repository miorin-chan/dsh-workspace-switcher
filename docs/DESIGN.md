# 设计与实现

本文记录 `dsh-workspace-welcome-switcher` 的设计边界与关键决定。
行为验证见根目录测试与实机检查记录。

## 目标

新会话页的工作区选择器在内置实现中是一个按注册顺序排列的扁平菜单。
工作区较多时，用户需要滚动查找，且常用与不常用的工作区混在一起。
插件要解决三个问题：常用工作区容易被找到、可以按名称或路径搜索、在列表很长时提供一个正式的选择空间，
而不是无限长的弹出菜单。

## 交互

选择器有两个形态，共用一个搜索输入框和同一份结果顺序。

紧凑形态锚定在工作区标签下方，宽度 360px，默认只渲染前五行。
顶部是搜索框，行内显示工作区名称、必要的路径后缀、相对活动时间和选中标记；标题已经表达目录名时省略路径后缀。
底部左侧是 **添加工作区**，右侧在结果超过五行时显示 **全部 N 个**，否则显示总数。

展开形态是居中的模态对话框，包含标题、搜索框、分组列表、结果数和添加入口。
未搜索时，列表分为 **最近使用**（前五行）与 **其他工作区**；搜索时合并为 **搜索结果**。
方向键移动高亮；存在高亮时 Enter 打开，Esc 返回紧凑形态，点击遮罩或关闭按钮退出。
两个形态都把焦点限制在面板内；展开形态打开期间锁定页面滚动。
标题旁的返回按钮让触摸设备也能回到紧凑形态。
输入法组合期间的 Enter 不触发选择，避免确认候选词时意外切换工作区。

两个形态都通过 `ReactDOM.createPortal` 渲染到 `document.body`，避免新会话页的定位或变换祖先影响固定定位。
展开形态进入时锁定页面滚动，退出时恢复原值。

按快捷键会直接进入展开形态。
`Mod+K` 显示按最近活动排序的会话，先过滤标题、工作区、路径和会话 ID，再合并宿主返回的消息正文命中。
`Mod+Shift+K` 按目录祖先关系组织工作区。
多个工作区共享的分叉目录也会成为可展开的节点，普通未归档会话挂在所属工作区下。
树节点采用侧栏的文件夹、展开箭头、会话状态点和 12px 层级间距。
当前会话所在分支会展开，筛选会保留命中节点的祖先。
在新会话页，目录节点用于展开，工作区节点用于选择。
选择动作交还给新会话页自己的 `onPick`。

## 数据语义

顺序来自 `useWorkspaces` 的工作区快照和 `useSessions` 的会话目录。
每个工作区的活动时间是成员会话 `updatedAt` 的最大值；没有成员会话时回落到工作区自身的 `updatedAt`。
子智能体会话不计入行内的会话数，但参与活动时间。
时间戳同时接受毫秒、秒和 ISO 字符串，以便对不同的 Host 投影保持稳健。

排序只发生在渲染层，不写回工作区注册表。
侧栏依赖的持久顺序保持不变；禁用插件不会留下排序副作用。

搜索按空白拆分词项，每个词项都必须出现在标题或完整路径中。
过滤不改变工作区顺序。

## 插槽与优先级

`conversation.hero.workspace` 是单值插槽：同一优先级只能有一个注册，最低优先级渲染。
插件以 `priority: -1` 注册，因此覆盖内置选择器；禁用或卸载后，内置实现重新成为最低优先级的注册。

`shell.overlay` 提供跨页面的弹窗。它和新会话页的展开选择器共享 `SwitcherDialog`、`SearchField` 和主题样式。
桌面端已有的 `session.search` 命令保留用户键位，插件替换它的执行动作，并通过快捷键服务注册工作区树命令。
命令拥有者热重载时重新绑定，插件卸载时恢复宿主动作并释放注册。

## 添加工作区的路径

内置选择器的目录流程由它自己的注册声明子洞 `conversation.hero.workspace.directoryFlow`。
单值插槽的同一个子洞只有一个声明者；覆盖注册不能再声明它，否则 SlotCore 会拒绝重复声明。
插件因此不渲染该子洞，而是直接使用已发布的服务：`ctx.uiWorkspace.pickDirectory()` 取得目录，
`ctx.workspaces.create({ path })` 采纳工作区，再把新 id 交给 owner 的 `onPick`。

添加入口只在目录流程子洞已有占位者时出现，占用信号来自 `ctx.slots.entries` 与 `ctx.slots.subscribe`。
这沿用内置选择器的判断，避免在没有目录选择组合时提供一个必然失败的按钮。
在应用内浏览目录的组合中，原生 Host 选择器可能不可用；失败信息保留在选择器内，由用户关闭或重试。

## 样式与可访问性

两个形态复用宿主 primitives 的表面语言，而不是另起一套外观。
紧凑形态是宿主 `Menu` 卡片：4px 内边距、34px 行高、`--dsw-specific-menu` 半透明底加 `--dsw-menu-backdrop-filter` 模糊、
`--dsw-elevation-prominent` 发丝描边阴影、14px 菜单图标、尾部 14px 对勾，
分组标题是 11/15 的三级文字；路径后缀与标题同行，标题先让位，保持菜单的单行节奏。
展开形态是宿主 `Modal` 卡片：`--dsw-alias-bg-layer-2` 表面、`--dsw-radius-panel` 圆角、16/24 标题、
32px 输入框和 28px 次要按钮，用 0.5px 的 `--dsw-alias-border-l3` 分隔标题、搜索与底部。
搜索框在紧凑形态采用命令面板的透明紧凑样式，在展开形态采用宿主的描边输入框。
其余样式同样只引用主题变量（`--dsw-alias-*`、`--dsw-radius-*`、`--dsw-font-family` 等），浅色与深色主题共用同一套结构。

悬停反馈只在支持悬停的设备上出现；焦点环使用宿主的 `--dsw-focus-ring-color`；滚动条复用宿主的 `--dsh-scrollbar-*` 变量；
减少动态偏好的用户不会看到入场、骨架和旋转动画。

组件不读取其他插件的 DOM，也不持久化任何自有状态。
所有时间与列表都在渲染时从标准 Hook 的切片计算。

## 验证

`node --test` 覆盖插槽注册、快捷键热重载与释放、新会话选区回调、最近使用排序、目录嵌套、树过滤，以及会话搜索合并。
实机可分别从已有会话和新会话页打开弹窗，确认键盘操作、主题适配、工作区配置失败反馈和关闭后的焦点。
