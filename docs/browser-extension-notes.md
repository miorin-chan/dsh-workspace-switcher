# 当前 DSH 接口核对

已连接的 DSH 0.2.2-rc.5 将会话和工作区浏览器注册到 `sidebar.workspaces`。
该插槽只向侧栏拥有者提供 `wide`、`expandSidebar` 和滚动绑定。
客户端的 `renderSlot` 限定于声明者授权的子插槽。
工作区包另外发布了 `workspace.picker`，可复用目录选择流程。
完整浏览器、视图选项和行操作由 `WorkspaceBrowser` 及其注册拥有。

`SessionGroupBy` 目前是 `flat`、`workspace` 和 `workspace-tree` 的封闭联合，`ViewOptionsMenu` 直接列出这三项。
搜索展开时原组件会隐藏部分顶栏动作。
把整块侧栏移到弹窗仍需为常开搜索、顶栏动作和弹窗独立分组状态提供参数。
如果两处同时挂载，还需明确目录流程和管理对话框的发起实例，当前请求源由侧栏注册共享。

## 保留内置侧栏的插件方案

弹窗插件继续通过 `shell.overlay` 呈现浏览器，复用 DSH 提供的会话与工作区快照、会话内容搜索、导航和目录选择流程。
弹窗拥有自己的视图菜单和分组记忆，内置侧栏继续管理自己的显示方式。
弹窗插件提供可观察的分组目录，独立的 `dsh-workspace-file-tree` 插件注册 `workspace-file-tree`，
并随启停即时更新弹窗菜单。

这个方案能实现起始视图、常开搜索和分组记忆，以及文件目录树的独立启停。
行布局、菜单和部分操作需要在弹窗实现，内置侧栏的新增行贡献与视图选项变化没有自动传入弹窗的接口。
文件目录分组也无法出现在内置侧栏的视图菜单中。

## 两处使用同一个浏览器的插件方案

若侧栏与弹窗必须共享组件和分组目录，可以维护一个替代工作区浏览器 bundle，
由显式的 profile 组合把原浏览器插件换成替代实现。
已安装的 DSH 应用与上游源码保持原样，两处由替代 bundle 提供同一套组件。
替代实现需要保留原注册和插槽标识，以及会话导航、目录流程、行操作、快捷键和状态持久化，
并用第三方插件和升级测试检查兼容性。
这需要用户接受替换当前 profile 的内置工作区插件，后续也需要跟进 DSH 版本。
